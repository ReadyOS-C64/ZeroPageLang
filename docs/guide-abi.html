Frames, recursion, and interop

Follow data across static and stack calls, and understand the ReadyOS boundary.

Static frames and return registers

Static calls copy arguments into fixed storage owned by the callee. The frame has program lifetime and is not reentrant. Record arguments copy flattened fields. Byte returns use A. Words and near pointers return low byte in A and high byte in X. Static aggregate results use return storage. Inspect the generated labels to follow the argument cells.

26_static_abi_metadata.zp64
const c64 = @import("c64");

memory {
    region call_stack: c64 at 0xc800 size 0x0400;

    stack in call_stack;
}

fn helper(a: u8, b: u8) callconv(.static) u8 {
    return a + b;
}

export fn main() callconv(.static) void {
    c64.console.clear();
    c64.console.print("ABI METADATA\n", .{});

    var total: u8 = helper(2, 4);
    if (total == 6) {
        c64.console.print("STATIC OK\n", .{});
        c64.vic.border = 5;
    } else {
        c64.console.print("STATIC BAD\n", .{});
        c64.vic.border = 2;
    }
}

Follow a record through static return storage

A Reading occupies three bytes. The caller copies its channel and both total bytes into adjust's parameter cells. The callee adds the delta to its own copy, writes all three result bytes to its return storage, and returns. The caller copies those bytes into first before calling the function again. The second call reuses the callee cells. The first result remains available in the caller.

aggregate-return.zp64
const c64 = @import("c64");

const Reading = struct { channel: u8, total: u16 };

fn adjust(input: Reading, delta: u16) callconv(.static) Reading {
    input.total += delta;
    return input;
}

export fn main() void {
    c64.console.clear();
    const original = Reading{ .channel = 3, .total = 0x12ff };
    const first = adjust(original, 1);
    const second = adjust(original, 2);
    const old_word: u16 = original.total;
    const first_word: u16 = first.total;
    const second_word: u16 = second.total;
    c64.console.print("ORIGINAL {x16}\n", .{old_word});
    c64.console.print("FIRST {x16} SECOND {x16}\n", .{ first_word, second_word });
    if (first.channel == 3 and first.total == 0x1300 and second.total == 0x1301) {
        c64.vic.border = 5;
    }
}

Build and run this example

Expect the original total 12FF and the two new totals 1300 and 1301. Copy the word fields into named u16 locals before formatting. In this preview, a direct field argument to {x16} prints its low byte with a zero high byte. The named word locals pass both bytes.

In the generated assembly, follow adjust_input_channel and adjust_input_total into the function, then adjust_return_channel and adjust_return_total into the caller's result cells. The high byte lives at adjust_return_total+1. A byte or word return would use registers instead of a record return area.

Generate assembly for the aggregate call

These static cells belong to the function for the life of the program. They are reused on every call, so a recursive or interrupt-driven re-entry can overwrite a live invocation. Use a pointer when the caller wants in-place mutation. For calls through the software stack or DLL ABI, choose supported scalar interfaces. A separate stack for recursion

Ordinary functions use fixed frame storage. For recursion, reserve RAM for the software stack and mark the recursive function with callconv(.stack). This example counts down to zero and returns the green border value. An exhausted software stack traps.

32_stack_recursive_border.zp64
const c64 = @import("c64");

memory {
    region call_stack: c64 at 0xc800 size 0x0400;

    stack in call_stack;
}

fn borderFrom(value: u8) callconv(.stack) u8 {
    if (value == 0) {
        return 5;
    }
    return borderFrom(value - 1);
}

export fn main() callconv(.stack) void {
    var border: u8 = borderFrom(4);
    c64.vic.border = border;
}

Compile the file and inspect the generated assembly for the entry and frame setup. The software stack holds the supported call-frame values. The 6510 hardware stack still holds CPU return addresses. Frame layouts and ABI limits

Configure a stack region in visible RAM. Its software stack and frame pointers use zero-page pairs. The 6510 hardware stack still holds the machine return address and compiler wrapper saves. The stack convention supports the documented scalar/pointer subset and checks frame bounds. Stack overflow traps. Avoid assuming every static-frame feature is available in a stack frame.

Exercise a stack limit with two nested calls

Follow main → relay → identity. At the deepest call the two functions still need their live frames and the bridge needs its saved frame linkage. In these fixtures every function uses the software stack. Both programs compile, but one byte in the stack reservation changes whether the deepest call can finish.

Ten bytes allow the call to finish

Complete passing host fixture
const test6502 = @import("test6502");

pub const zeropage_options = .{
    .stack = .{ .base = 0xc8fc, .size = 10 },
    .abi = .{ .default_frame = .stack },
};

fn identity(value: u16) u16 {
    return value;
}

fn relay(value: u16) u16 {
    return identity(value);
}

export fn main() void {
    test6502.expectEqualU16(1, 0x805a, relay(0x805a));
}

Nine bytes reach the overflow trap

Complete runtime-failure fixture
pub const zeropage_options = .{
    .stack = .{ .base = 0xc8fc, .size = 9 },
    .abi = .{ .default_frame = .stack },
};

fn identity(value: u16) u16 {
    return value;
}

fn relay(value: u16) u16 {
    return identity(value);
}

export fn main() void {
    _ = relay(0x805a);
}

Starting at $c8fc, ten bytes have the exclusive end $c906 and nine have $c905. The passing fixture checks that $805a reaches the caller intact through A and X. The smaller reservation enters zeropage_stack_overflow_trap before the overflowing call. The runner checks that path separately from the result assertion.

Use the boundary as a way to test your sizing assumptions. The compiler can compact private frames in eligible builds, so the ten-byte result describes this call chain and configuration. Test the deepest supported path of your actual program. Hardware-stack depth from JSRs, wrapper saves, and interrupts is a separate budget.

Run both sides of the stack boundary

Follow a word argument through a nested call

Use the ten-byte fixture from the previous section. The software stack grows upward. The frame pointer names the active frame's base, while the stack pointer names the first free byte. Each of these private frames stores one word. Before a nested call the bridge also stores the old frame pointer so it can restore the caller.

$c904–$c905identity argument5a 80
  1. Before relay calls identity, SP is $c902. The bridge adds four and compares the candidate $c906 against the configured exclusive end. Equality passes. With a nine-byte reservation the limit is $c905, so the guard traps before storing the frame link.
  2. The bridge stores the old FP at SP, advances SP two bytes, copies the word into the new frame, sets FP to $c904, then advances SP to $c906. JSR identity puts its return address on the hardware stack.
  3. identity loads offset 1 into X, then offset 0 into A. On return to relay, the bridge saves A with PHA, sets SP back to the saved-link address, restores FP from the link, and restores A with PLA. X still holds the high byte. The caller finally receives $805a.

Measure both stacks on a nested workload

Both fixtures run the same 48 updates and assert the same final word. Each update calls a second helper while its own frame is live. The static version gives the two helpers fixed storage. The stack version places their arguments and locals in a configured software stack while keeping the entry and loop driver static.

The write extent is the distance from the software-stack base to the highest byte written, inclusive. Frames can reserve bytes they never write. To check capacity, exercise the deepest call path and include its frame linkage and any compiler-reserved slots. The measured hardware stack is relative to the host runner's starting point. IRQs and firmware activity can add to it on a C64.

Use static frames when calls run to completion without re-entry. A second invocation of the same static function would share argument and local cells. Software-stack frames allow supported recursion and give each call its own cells. They do not make interrupt re-entry into shared runtime helpers safe. Keep interrupt handlers within a separately defined machine contract.
